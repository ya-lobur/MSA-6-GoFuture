# Каталог доменных событий GoFuture

## Контекст

В событийно-ориентированной архитектуре GoFuture вся межсервисная асинхронная коммуникация осуществляется через доменные
события, публикуемые в Apache Kafka. Схемы событий управляются через Confluent Schema Registry (Avro/Protobuf) с
политикой
обратной совместимости (BACKWARD).

Каждое событие следует стандартизированному формату конверта, основанному на спецификации CloudEvents.

## Формат конверта события

| Поле             | Тип      | Описание                                               |
|------------------|----------|--------------------------------------------------------|
| `event_id`       | UUID     | Уникальный идентификатор события                       |
| `event_type`     | string   | Тип события (например, `BookingCreated`)               |
| `aggregate_id`   | UUID     | Идентификатор агрегата (бронирование, водитель и т.д.) |
| `aggregate_type` | string   | Тип агрегата (`Booking`, `Driver`, `Payment`)          |
| `timestamp`      | datetime | Время создания события (UTC, ISO 8601)                 |
| `region`         | string   | Регион события (`sea`, `latam`, `cis`)                 |
| `version`        | int      | Версия схемы события                                   |
| `source_service` | string   | Сервис-источник события                                |
| `correlation_id` | UUID     | Идентификатор корреляции для трассировки Saga          |
| `payload`        | object   | Полезная нагрузка (зависит от типа события)            |

## Каталог событий по сервисам

### Booking Service

Агрегат: **Booking**

| Событие                  | Описание                                          | Публикуется когда                                |
|--------------------------|---------------------------------------------------|--------------------------------------------------|
| `BookingCreated`         | Пассажир запросил поездку                         | Создан запрос на бронирование                    |
| `BookingPriceCalculated` | Стоимость поездки рассчитана и подтверждена       | Получен ответ от Pricing Service                 |
| `BookingDriverAssigned`  | Водитель назначен на поездку                      | Водитель принял назначение                       |
| `BookingConfirmed`       | Бронирование подтверждено, все шаги Saga пройдены | Платёж авторизован, водитель назначен            |
| `BookingCancelled`       | Бронирование отменено                             | Отмена пассажиром, системой или компенсация Saga |
| `BookingFailed`          | Бронирование не удалось, запущена компенсация     | Сбой на одном из шагов Saga                      |
| `RideStarted`            | Поездка началась                                  | Водитель начал маршрут                           |
| `RideCompleted`          | Поездка завершена                                 | Водитель завершил маршрут                        |
| `RideRated`              | Пассажир оценил поездку                           | Пассажир оставил оценку                          |

### Driver Service

Агрегат: **Driver**

| Событие                     | Описание                                      | Публикуется когда                               |
|-----------------------------|-----------------------------------------------|-------------------------------------------------|
| `DriverLocationUpdated`     | Обновлены GPS-координаты водителя             | Периодическое обновление с устройства (1–5 сек) |
| `DriverStatusChanged`       | Статус водителя изменён (online/offline/busy) | Водитель переключил статус                      |
| `DriverAssignmentRequested` | Запрос на назначение водителя                 | Booking Service запрашивает назначение          |

Агрегат: **FraudCheck**

| Событие               | Описание                                | Публикуется когда                          |

## Версионирование схем

### Политика совместимости

- **Режим**: BACKWARD — новые потребители могут читать старые и новые версии событий
- **Реестр**: Confluent Schema Registry хранит все версии схем
- **Формат**: Avro для большинства событий; Protobuf для высокочастотных (`DriverLocationUpdated`)

### Правила эволюции схем

1. Новые поля добавляются только с значениями по умолчанию
2. Удалённые поля остаются в схеме как deprecated на одну мажорную версию
3. Переименование полей запрещено — создаётся новое поле, старое помечается deprecated
4. CI/CD-пайплайн валидирует совместимость перед деплоем через Schema Registry API

### Семантическое версионирование

- **v1 → v1** (patch): добавление optional-поля → совместимо
- **v1 → v2** (major): изменение типа поля, удаление required-поля → несовместимо, параллельный топик
