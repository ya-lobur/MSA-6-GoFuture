# Задание 2. Проектируем Event-Driven архитектуру

Чтобы обрабатывать более 500 тысяч конкурентных поездок и реализовать динамическое ценообразование, требуется
распределённая архитектура с возможностью обрабатывать события в реальном времени. Спроектируйте архитектуру событийной
платформы, в которой:

- Используется модель доменных событий, таких как BookingCreated, DriverLocationUpdated и другие.
- Определена схема топиков Kafka с партиционированием по регионам.
- Для реальной обработки событий задействованы потребители (например, KStreams или Flink).
- Выбран вид Saga и проработаны соответствующие события.
- Реализованы механизмы обеспечения надёжной доставки.
- Выбраны подходы к мониторингу и составлен список метрик.
- Инструменты для мониторинга определены и интегрированы в архитектуру To-Be.

## В результате у вас должно получиться

- Диаграмма C2 с архитектурой событийной платформы.
- Текстовое описание подхода к мониторингу с обоснованием и списком метрик.
- Список выбранных инструментов мониторинга и их отражение на диаграмме С2.
